# agent4novel 开发与迭代

目标是完成当前票据或已授权的节点改进。Harness 提供运行源信息；本 skill 规定怎样定义验收、派工、核验证据和收敛。第一次运行从下方“验收准备”开始，恢复时先读本票 Wiki 的最新记录。

## 入口与职责

- 主 Agent 负责需求解释、验收定义、eval 执行、范围检查和结果裁决；产品实现及修复交给实施子 Agent。
- 只读 reviewer 检查验收是否偏离原目标、能否被错误实现骗过。正式双轴 review 继续按项目完成清单执行，reviewer 不参与候选实现。
- 开发前完整读 [Ticket 完成审核清单](../../../docs/agents/ticket-completion-checklist.md)，按 [Wiki skill](../agent4novel-wiki/SKILL.md) 定位当前票面及工程上下文。CLI、模型配置和未知结果恢复复用 [drive skill](../agent4novel-drive/SKILL.md)，以实际 help 和代码确认能力。
- 正常流程由 Agent 自主校准、派工和验收，不逐票等待人工批准。真实目标冲突、无法从已有决定确定的产品取舍或新增权限，明确报告缺口；测试与执行中的普通问题自行解决。

## 验收准备：在派工前完成

1. **追溯目标。** 回读 issue 的 WHAT/AC、当前用户决定与非目标。每条标准标记来源；补充假设单列。确定本次范围、原有行为回归面、候选固定点、调用预算和停止条件。当前对话的明确修订优先，必要时同步票面，保留旧决定的变化原因。
2. **定义方法。** 对每条目标写出固定材料/初始状态、实际入口、可观察预期、源证据、通过及失败条件。预期来自需求、不变量或独立样例，避免从候选输出反推期望。新行为测试在原基线应因缺少目标行为失败；环境/夹具错误不算有效 RED。
3. **校准辨别力。** 针对关键目标构造可以骗过弱验收的错误结果，例如空值冒充完整捕获、读取当前配置冒充历史快照、模型成功冒充作品保存成功。证明方法会拒绝这些结果；已有正确路径应继续通过。实现尚不存在时明确哪些校准已执行、哪些须在候选产生后完成。
4. **只读审查。** 将原目标与验收方法交给未参与实现的 reviewer，要求找目标偷换、遗漏、可作弊通过方式和范围膨胀。处理发现后保存验收版本/摘要及 hash。前置审查计入当前任务预算，不递归创建评审体系。
5. **固定派工。** 给实施子 Agent 明确写入范围、验收版本、公开测试接缝、TDD 切片、验证命令和证据要求。验收标准与受保护材料属于主 Agent；实施子 Agent 可新增开发测试或提出纠错，改变判定依据须单独说明并重做受影响校准。

完成条件：每条目标都有可执行验证与独立期望；关键假通过有识别方法；未验证项如实标出；验收版本与派工范围可回读。新票首次验收方法可参考 [#51 验收准备](../../../docs/plans/node-iteration-acceptance.md)，不把其具体案例套用到所有票。

## 实现与复验：默认两轮，上限三轮

一轮是“实施子 Agent 提交候选 → 主 Agent 实际验收 → 裁决”，首次实现计第 1 轮。提前通过就结束；第 2、3 轮只修已发现的本票差距。

- 实施子 Agent 按 TDD 完成最小贯通切片，提交精确文件、固定候选、测试命令/原始输出和已知限制。它自己的测试通过报告是待核验证据。
- 主 Agent 检查固定点到候选的完整 diff、依赖/存储/公共入口变化和验收材料是否被改动；在该候选上亲自执行 eval、读取源记录和回归结果。
- 每条标准只判 `PASS`、`FAIL` 或 `证据不足`，附候选版本、命令与源证据。必需项全部 PASS 才通过；未知结果不计成功。固定基线的失败、所有调用和不利结果同样保留。
- 未通过时，给实施子 Agent“目标条目、复现方式、预期/实际、证据”的修订任务。实现细节由它决定；主 Agent 保持验收角色。新增接口、依赖或抽象必须能解释其与已确认差距的关系。
- 改变标准时保留旧版本，说明原需求依据和原因，重跑受影响反例与验收；轮数继续累计，不能重新计轮绕开上限。
- 到第 3 轮或实际预算耗尽即结束本轮执行。未达标保持未完成，报告剩余差距和继续条件；阶段目标“完成二期”不允许覆盖单票失败或开启无界优化。

工程 eval 通过后，执行项目原有双轴 review、attestation 和已授权的发布步骤；这个循环不取代完成清单，也不扩大推送、合并或付费调用授权。

## 节点效果迭代

先读取本次运行可获得的源信息，形成“观察 → 假设 → 最小改动 → 复跑 → 对照 → 决定”。完整输入、实际 SDK 参数和输出优先于聊天总结；没有捕获的信息保持 `None`/`null`，不补造。承诺必需捕获却缺失时判记录不完整。

复用可比旧 A，只运行必要的 B；核对输入、实际 SP、代码和模型参数差异。用户原话、Agent 观察/推断和下一轮假设另存本轮评论，不修改机器源记录。普通文件 diff、评论文件和 run-step 足够时直接复用；不另建评分/实验管理平台。

只要求读取或 diff 时停在该结果。模型调用沿用已明确授权与预算；本地 mock 联验不证明文学质量。缺少既定质量依据时呈现原输出与比较证据，效果保持待确认。

## 留下什么

本票 Wiki 保存验收版本、轮次、候选、逐项结论、失败修订和下一步；issue 保存 WHAT/AC及真实生命周期。私有运行目录保存源信息和本轮评论。复用已有位置，避免多处维护同一状态。

最终报告分清：工程实现、eval、主观效果、PR/merge/远端验证。逐轮列出实际差距与变化；未发生的动作保持未完成。
