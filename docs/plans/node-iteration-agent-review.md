# 通过Agent迭代节点能力

2026-10-07。用户认可三个简单动作，并要求减少用不上的工作。本文件是[最小有效工作流](./node-iteration-workbench.md)的对话使用说明，尚未实现新增工具，也不是已执行模型实验的记录。

## 一次迭代怎样开始

最好从一个看得见的问题开始，例如某段正文不自然、必要设定没起作用，或节点输出被截断。Agent先查看当前实际输入输出，再提出本轮最小修改。已有材料和明确授权直接使用；用户已让Agent开始/继续迭代且调用授权与预算明确时，必要复跑可自主完成，不必每一步重复批准。只要求review或diff时停在对应结果；缺项影响判断或执行时才询问。

## 三种自然语言操作

下表均为假设交互示例：

| 你说 | Agent做 |
| --- | --- |
| “这段对话太像旁白，先看问题在哪” | 读相关原输出、实际输入与当前指导，给依据明确的检查结论/假设 |
| “先改这一处，给我看diff” | 改相关SP/context/Harness，说明改动和本轮假设，不自动调用模型 |
| “改完跑一下，输入输出给我看” | 核对已有授权/条件，保存并运行新版，展示实际输入输出与状态 |
| “和上次A比一下” | 先核对可比条件，能复用A记录就只跑新B；条件不同明确标出 |
| “B自然些，但第二段还是讲道理” | 保存对应版本的comment，定位第二段，提出下一次具体修改 |
| “看看是不是context里没放那条设定” | 检查实际输入中的来源和内容，区分缺失、未遵循与暂时无法判断 |
| “全文展开，其他先不用” | 读取对应原输出，不重生成或改写成新例子 |
| “这版保留，以后的生成用它” | 对象明确时按该版本接回，执行项目原有工程流程 |

## 简短的对话示意

下面不是实际运行结果：

> 你：这段不自然，先看看输入输出。
> Agent：定位具体段落，核对输入与指导，提出一个修改假设。
> 你：改SP这一句，再跑一次。
> Agent：展示diff、保存新版条件并运行B；复用可比的旧A做对照。
> 你：B好些，但第二段还要改。
> Agent：保存comment，针对第二段继续修改。

这就是主要Human-in-loop。用户表达判断与comment，Agent承担检查和操作，不要求每轮完成评分、审批或固定次数的运行。

## 必要的记录与边界

保存当前节点、输入与实际版本/参数、原输出和运行状态、用户原话comment。Agent解释另列，不改写成用户决定。A/B只指当前明确的两版，旧记录与失败保留。

未看到实际请求时，Agent说明只能核对源材料；不能把推测的装配当真实输入。重复生成不是默认动作，复用旧记录也不冒称新样本。需要重复或更多案例时，说明它要解决哪个当前不确定性。

手改文本作为参考，不计为模型输出；实验中的偏好不自动修改作者作品。普通指代唯一时直接处理，只有影响正确性、授权或实际操作的歧义才追问。
