# 节点能力迭代：最小有效工作流

2026-10-07。用户已确认通过Agent使用，核心动作是review/modify、review输入输出、review A/B + comment；进一步要求从第一原理减少冗余。本版据此调整，尚未实现新增记录/预览能力，未执行新的模型实验。先前草稿保留为本地设计历史。

## 要解决的问题

每次迭代只要回答：节点实际拿到了什么，实际产出了什么，哪里不符合当前目标，下次具体改什么，改后有没有改善。

用户用自然语言指出问题和评论，Agent负责查材料、修改、调用CLI和保留结果。能帮助观察、判断、修改或验证的步骤留下；不能服务这条反馈循环的机制不进入第一期。

## 默认循环

选一个具体问题/案例 → review实际输入输出 → 判断优先改哪一层 → modify一处 → 用相同源材料复跑 → 必要时review A/B → comment → 保留或继续改。

一轮先解决一个问题。不要求固定的案例数、重复次数、评分表、评阅角色、会话/采用卡或专用界面。已有问题和授权直接沿用，不逐项重新询问。

## 先定位，再修改

| 观察到的现象 | Agent先核对 | 修改优先级 |
| --- | --- | --- |
| 输出缺少某条必要设定/前章信息 | 实际输入有没有该信息，是否被省略/截断 | 输入确实缺失时先改context，不让SP猜未提供的信息 |
| 输入已有相关信息，输出仍偏离目标或表达不自然 | 对应输入与输出原文、当前指导是否明确、是否只是一次波动 | 提出可验证的SP/context表达假设，先改最小相关部分 |
| 超时、截断、解析/格式失败或看不到实际请求 | 调用记录、输出限制、schema、期限与装配/记录接缝 | 先处理Harness问题，不把技术失败直接归为文学质量差 |

表格是检查顺序与修改优先级，不是只凭现象即可确定原因。Agent区分观察、推断和验证；无证据时说明具体缺项。

## 三个操作怎样配合

- Review / modify：需要时展示当前SP、context装配或Harness相关部分；每次给改动diff和一句本轮假设。
- Review输入输出：读实际送入模型的内容和原输出，按当前问题展开，完整材料随时可读取。
- Review A/B + comment：需要判断改动收益时才比较。固定源材料和上游内容，除待测因素外固定其他可控制条件；评论绑定对应两版。

A/B不要求每次都重新跑两版。已有A的输入、SP/代码版本、模型参数与其他条件可核对且可比时，直接复用其记录，只跑新B，并明确A是历史结果。条件不同就说明不同，不把它称作只改一个因素的对照。复用结果/缓存不算新的重复样本。

普通的小改先看一次结果。效果含糊、波动明显或改动较大时，再重复或增加案例。候选准备接回生产时，按改动执行必要工程测试和链路检查；不靠单次样例宣称稳定改善。

## comment怎样推动下一步

Agent保存你的原话，再归纳一个具体的下一步问题。例如“第二段还在讲道理”，先定位对应输出和指导，提出下一次最小修改；不把单段意见扩成所有场景的硬规则。

调用按当前任务授权执行：只要求review或看diff时，Agent先停在对应结果；明确让Agent开始/继续迭代，且已有模型调用授权和预算时，Agent可以完成必要修改和复跑，不必每条comment后重复请求同样许可。comment本身不扩大任务范围、费用或数据授权。手改或拼接的文本作为参考，不算模型新产出；若希望模型产生类似效果，再修改基础能力并验证。

普通表达对象唯一时直接处理。需要接回基础版本时，你明确说“以后的生成用这版”，Agent根据当前明确版本和项目既有审核流程执行，不增加专用采用卡。

## Agent最少需要的材料

一轮一个私有本地目录：节点与版本、实际输入、实际SP/代码与模型参数、原输出/真实运行状态、评论和下一步。Agent自动保存和读取，不要求用户管理目录或编辑JSON。首次结果、失败与旧版本不覆盖；需要恢复时读取记录，不只凭聊天记忆。

默认回复只展示当前问题、相关差异和结果；详细SP、完整上下文和全部运行信息按需展开。参数或材料缺失时如实说明，不补造输出、成本或成功状态。

## 第一版只补两个底层缺口

1. 实际调用可检查：让Agent能看到生产装配真正产生的system/user内容及原输出，预览与实际执行共用同一接缝。
2. 本次结果与评论可保存、重读：使用简单本地文件即可，记录对应版本与条件，不先建立实验管理平台。

其余复用现有run-step：它已支持六节点独立运行、自定义基础SP、固定上游和现有参数，返回校验后的content与遥测；--system-prompt-file替换本次基础SP，作品Prompt/Skill则是追加指导。Context/Harness超出现有开关的改动通过明确代码版本实验。

当前尚无通用完整装配输入导出；只能确定看到源材料，不能将手工推测的prompt称作实际请求。相关运行方法见[Wiki014](../wiki/014-agent-cli-telemetry.md#单节点实验-run-step)，已有SP经验见[Wiki011](../wiki/011-caption-creative-directions.md#caption-sp-迭代方法)。外部评测工具不属于本票或第二期核心依赖，若以后需要另立 research 文档和接入范围。

## 最小验证与下一步

先用正文节点的一个真实问题贯通：Agent读当前输入输出、修改SP或相关装配、运行新版、在需要时比较A/B、记录一条comment并继续。复跑前先核对已有记录，能复用的不重复生成。具体对话见[Agent操作方式](./node-iteration-agent-review.md)。

完成条件是这条循环可执行且材料能重读，不是文档齐全或构建了更多抽象。新记录/预览能力与真实模型效果仍待开发和验证；实验不改写作者作品，公共遥测不增加正文或完整prompt。
